# **【開発作成指示書】音楽メディアからの自動採譜・PDF楽譜生成システム（TohoStudio連携版）**

## **1\. 開発概要**

本案件は、TohoStudio環境（Macクライアント）および内蔵Linux VM（バックエンドサーバー）において、音楽メディア（WAV/MP3/M4A等）から音程・リズムをAIモデルを用いて高精度に自動抽出し、五線譜PDFとして出力・保存する機能を実装するための指示書である。  
重い音楽信号処理・採譜・楽譜組版処理はLinux VM上のPythonデーモンで処理し、TohoStudio（Swift/macOS）側からはREST API通信経由でシームレスに利用可能なハイブリッド構造を採用する。

## **2\. システム構成と役割分担**

\[ホスト Mac / 仮想Mac (TohoStudio)\]  
  │  
  │ (Swift / SwiftUI / PDFKit)  
  │  1\. 音声ファイル入力（SoundMaker / 素材スタジオ）  
  │  2\. Multipart HTTP POST リクエスト送信 (ポート 8080\)  
  │  
  ▼  
\[ゲスト Linux VM (VirtualBuddy / Ubuntu ARM64)\]  
  │  
  │ (Python 3 / FastAPI / Uvicorn デーモン)  
  │  3\. Basic Pitch（Spotify OSS）によるピッチ・発音時刻の抽出・MIDI生成  
  │  4\. music21 による拍・音価のクオンタイズ・楽譜構造化  
  │  5\. LilyPond による組版レンダリング・PDF生成  
  │  6\. PDFバイナリのレスポンス返却  
  │  
  ▼  
\[ホスト Mac / 仮想Mac (TohoStudio)\]  
  │  7\. 受信したPDFのプレビュー表示（PDFKit）  
  │  8\. ファイル保存（AssetStudio / ローカルストレージ）

## **3\. バックエンド環境構築・実装指示（Linux VM側）**

本機能は、LLMMac.md に記載されている「Toho-Studio 専用 API デーモン（ポート 8080）」へ統合・拡張する。

### **3.1. 依存パッケージおよびツールの追加**

Linux VMのセットアップ手順において、以下のシステムパッケージとPythonライブラリをインストールすること。

> * **APTパッケージ**:  
>   sudo apt-get update && sudo apt-get install \-y lilypond ffmpeg

> * **Python依存関係 (/opt/tohostudio-server/requirements.txt)**:  
>   basic-pitch\>=0.2.0  
>   music21\>=9.1.0  
>   pydub\>=0.25.1  
>   python-multipart\>=0.0.9

> * **反映コマンド**:  
>   /opt/tohostudio-server/venv/bin/pip install \-r /opt/tohostudio-server/requirements.txt

### **3.2. デーモン拡張実装 (/opt/tohostudio-server/llm\_server\_daemon.py)**

既存のデーモンファイルに以下のモジュール・関数・APIエンドポイントを組み込むこと。

> 1. **インポートと環境設定**:  
   * basic\_pitch.inference.predict および basic\_pitch.ICASSP\_2022\_MODEL\_PATH をインポート。  
   * music21.environment.set('lilypondPath', '/usr/bin/lilypond') を設定。  
> 2. **MIDI→PDF変換関数 (convert\_midi\_to\_pdf)**:  
   * music21.converter.parse(midi\_path) でMIDIを読み込み。  
   * score.quantize(quarterLengthDivisors=(4,), processOffsets=True, processDurations=True) で16分音符基準のクオンタイズを実行。  
   * score.analyze('key') で調号を推定・設定。  
   * score.write('lily.pdf', fp=temp\_ly\_path) でLilyPondを経由したPDFコンパイルを実施。  
> 3. **APIエンドポイント定義**:  
   * **パス**: POST /v1/audio/transcribe-to-sheet  
   * **リクエスト**: file: UploadFile \= File(...)（拡張子チェック: wav, mp3, m4a, flac, ogg）  
   * **処理**:  
     * アップロード音声の一時保存。  
     * predict() により発音開始時刻（onset\_threshold=0.5）とピッチを抽出しMIDIを出力。  
     * 生成されたMIDIをPDFへ変換。  
   * **レスポンス**: FileResponse（MIMEタイプ: application/pdf）

## **4\. フロントエンド実装指示（TohoStudio / Swift側）**

main.md に基づき、Swift側の「SoundMaker」または「TohoAIStudio」から呼び出せる共通サービスおよびビューを実装すること。

### **4.1. 通信クライアントクラスの新規作成**

> * **配置先**: TohoStudio/Sources/TohoStudio/Services/MusicTranscriptionClient.swift  
> * **機能要件**:  
  * 接続先ホストは CloudVirtualLinuxService.swift の hostIP（初期値 192.168.64.3:8080）を参照可能とすること。  
  * transcribe(audioFileURL: URL) async throws \-\> Data メソッドを実装。  
  * multipart/form-data 形式でリクエストを生成。  
  * 音声解析とPDF生成処理に時間を要するため、URLRequest.timeoutInterval は **180秒** に設定すること。

### **4.2. プレビュー＆保存UIコンポーネントの作成**

> * **配置先**: TohoStudio/Sources/TohoStudio/Views/ScoreViewerSheetView.swift  
> * **機能要件**:  
  * **ファイルピッカー**: .fileImporter でオーディオファイルを選択可能とする。  
  * **進行状況表示**: 処理中は ProgressView（インジケーター）を表示。  
  * **PDFプレビュー**: NSViewRepresentable を用い、PDFKit.PDFView で生成されたPDFをリアルタイム表示。  
  * **エクスポート機能**: NSSavePanel を起動し、指定パス（AssetStudio保管先等）へPDFファイルを書き出し可能とする。

## **6\. テスト・受入基準**

> 1. **ヘルスチェック確認**:  
   * ホストMacターミナルから curl http\://\<VM\_IP\>:8080/health を実行し、デーモンが OPERATIONAL を返すこと。  
> 2. **単体APIテスト**:  
   * 任意のWAV/MP3ファイルを POST /v1/audio/transcribe-to-sheet に送信し、正常にPDF形式のバイナリが返却されること。  
> 3. **楽譜品質確認**:  
   * 出力されたPDFが破損しておらず、音符・五線譜・拍子・小節線が適切にレンダリングされていること。  
> 4. **TohoStudio統合テスト**:  
   * アプリUIから音声ファイルを選択し、約10〜30秒程度で画面上にPDFが表示され、ローカルへの保存が正しく完了すること。
